## 2. DAX（Data Analysis Expressions）

- Power BIでデータを`計算・分析するための数式言語`。
- `DAX`は、すでに読み込まれているデータモデルを基準に`分析値を計算`するときに使用する。
- ` 列またはテーブルを参照`して数式を作成する。
- データ分析に使用できるさまざまな関数を提供する。

<img src="images/image-7.png" width="550">

#### 1) DAX構文

```sql
名前 = 関数(テーブル名[列名])
```

例：

```sql
総売上 = SUM('販売'[売上])
```

#### 2) DAX演算子

実務でよく使用する演算子を中心に整理する。

| 種類 | 演算子 | 意味 | 例 |
|---|---|---|---|
| 算術 | `+` | 加算 | `[売上] + [追加額]` |
|  | `-` | 減算 | `[売上] - [原価]` |
|  | `*` | 乗算 | `[単価] * [数量]` |
|  | `/` | 除算 | `[売上] / [数量]` |
| 比較 | `=` | 等しい | `[地域] = "東京"` |
|  | `<>` | 等しくない | `[地域] <> "東京"` |
|  | `>` | より大きい | `[売上] > 1000000` |
|  | `<` | より小さい | `[売上] < 1000000` |
|  | `>=` | 以上 | `[売上] >= 1000000` |
|  | `<=` | 以下 | `[売上] <= 1000000` |
| 論理 | `&&` | AND（両方の条件を満たす） | `[売上] > 1000000 && [地域] = "東京"` |
|  | `\|\|` | OR（いずれかの条件を満たす） | `[地域] = "東京" \|\| [地域] = "大阪"` |
|  | `NOT` | 条件を否定する | `NOT([地域] = "東京")` |
| 文字列 | `&` | 文字列を連結する | `[姓] & [名]` |

## 3. 新しいメジャーと新しい列(計算列)

Power BIでは、テーブルに新しい値を追加する方法として `新しいメジャー`と`新しい列` がある。

<img src="images/image-8.png" width="550">

---

#### 1) メジャー（Measure）

SQLの`集計関数`のように、`列を参照して合計・平均・件数などを動的に計算する`。

- テーブルに新しい列は追加されず、計算結果も行ごとの値として保存されない
- フィルターやビジュアルで設定された項目に応じて、計算結果が変わる
- 主にビジュアルの「値」に使用する
- 計算列よりデータサイズへの影響が小さい

例：総売上を計算

```sql
総売上 = SUM('販売'[販売金額])
```
→ 現在のフィルター条件に応じた販売金額の合計を求める。

#### - メジャーの確認

作成したメジャーは「`データ`」ペインで確認できる。

- メジャーの前には電卓アイコンが表示される
- 実際の計算結果はレポートのビジュアルに配置して確認する

<img src="images/image-9.png" width="200">

※ SQLでは `GROUP BY` と集計関数を使って集計するが、DAXのメジャーは `フィルターコンテキストに応じて動的に再計算される`。

---

#### 2) 計算列（Calculated Column）

SQLの`単一行関数`のように、`各行ごとに数式を計算して結果を保存する`。

- テーブルに新しい列を追加
- 行単位で計算
- 軸・凡例・値などに使用可能
- データセットのサイズが増加する

例：利益を計算

```sql
利益 = '販売'[販売金額] - '販売'[原価]
```

→ 各行ごとに `販売金額 - 原価` を計算する。

<img src="images/image-10.png" width="650">

---

#### - 計算列とメジャーの使い分け

- `レポート上で条件に応じて集計結果を変化させたい` → メジャー
- `行ごとに値が必要` → 計算列

#### 5) メジャー vs 計算列

| 区分 | メジャー | 計算列 |
|---|---|---|
| 計算タイミング | ビジュアルの表示時 | データ更新時 |
| 計算単位 | `フィルターされたデータ` | `行単位` |
| 結果 | 必要なときに計算 | 各行に値を保存 |
| 代表例 | SUM(売上) | 数量 × 単価 |
| データサイズ | モデルサイズへの影響が小さい | `列が追加される` |
| 主な用途 | `集計、KPI、分析` | `分類、派生列` |
| 代表的な関数 | `SUM`、`AVERAGE`、`COUNTROWS` | `IF`、`SWITCH`、`YEAR` |

## 7) DAX関数を使用した計算列の追加

#### # IF関数

```sql
売上区分 = IF('販売'[販売金額] >= 500000, "高額", "一般")
```

<img src="images/image-25.png" width="700">


#### # SWITCH関数

1) **値を比較する場合**

```sql
SWITCH(比較する値, 値1, 結果1, 値2, 結果2, ...)
```

```sql
商品区分 = SWITCH('販売'[商品], "ノートパソコン", "PC", "モニター", "ディスプレイ", "キーボード", "周辺機器", "マウス", "周辺機器", "その他")
```
![alt text](images/image-32.png)

2) **条件・範囲を比較する場合**

`>`, `<`, `>=`, `&&` などの条件式を使用する場合は `SWITCH(TRUE())` を使う。

```sql
SWITCH(TRUE(), 条件1, 結果1, 条件2, 結果2, ...)
```

```sql
地域区分 = SWITCH('販売'[地域], "東京", "首都圏", "埼玉", "首都圏", "大阪", "大都市圏", "その他")
```

![alt text](images/image-24.png)

## 8) DAX関数を使用したメジャーの追加

```sql
売上ランク = SWITCH(TRUE(), [総売上] >= 30000000, "A", [総売上] >= 10000000, "B", "C")
```

![alt text](images/image-26.png)

#### # DIVIDE関数

0で割る場合のエラーを防ぐため、`/` より `DIVIDE()` の使用を推奨する。

- `7 / 0` → `∞`
- `DIVIDE(7, 0)` → `BLANK`

```sql
売上利益 = [総売上] - [総原価]

売上利益率 = DIVIDE([売上利益], [総売上])
```

# 1. 프로젝트 개요 및 문제 정의

## 1.1 프로젝트명

**서울 지하철 역세권의 교통 이용량과 부동산·상권 특성 분석**

## 1.2 프로젝트 주제

### 분석 대상

서울 지하철역을 중심으로 일정 반경의 역세권을 설정하고, 해당 지역의 **지하철 이용량·버스 이용량·부동산 가격·부동산 거래량·상권 규모·지역 특성** 등의 데이터를 결합하여 분석한다.

초기 분석 대상으로 **서울 지하철 2호선**을 선정하고, 데이터 확보 및 분석 가능 여부에 따라 서울 전체 지하철역으로 범위를 확대한다.

### 해결하고자 하는 문제

지하철 이용량이 많은 역세권일수록 실제로 부동산 가격과 상권 규모가 높은지 확인하고, 교통 이용량과 역세권 특성 사이에 어떠한 관계가 존재하는지 분석한다.

또한 단순히 이용량이 많은 지역의 가격이 높다는 현황 비교에 그치지 않고, **인구·상권·업무시설 등 지역 특성을 함께 고려하여 교통 이용량과 부동산·상권의 관계를 분석**한다.

### 분석 기간

**최근 확보 가능한 연도 데이터를 기준으로 하되, 가능할 경우 2019~2025년의 시계열 데이터를 활용한다.**

### 분석 지역/대상

* 1차 분석: 서울 지하철 2호선 역세권
* 2차 분석: 데이터 확보 가능 시 서울 전체 지하철역
* 역세권 기준: 지하철역 중심 반경 500m~1km
* 주요 분석 단위: 개별 지하철역 및 역세권

---

## 1.3 기획 배경

서울의 부동산 가격과 상권은 지역별로 큰 차이를 보이며, 교통 접근성은 이러한 지역 특성을 결정하는 주요 요소 중 하나로 인식되고 있다.

그러나 단순히 특정 지역의 부동산 가격이 높다는 사실만으로는 **대중교통 이용량과 부동산 및 상권 사이의 관계**를 확인하기 어렵다.

따라서 본 프로젝트에서는 지하철역별 이용량을 기준으로 역세권의 부동산 및 상권 데이터를 결합하여 분석하고자 한다.

특히 강남역, 성수역, 홍대입구역, 잠실역 등 서로 다른 특성을 가진 역세권을 비교하여 다음과 같은 관계를 확인한다.

* 지하철 이용량이 많은 지역의 부동산 가격은 높은가?
* 교통 이용량과 상권 규모는 어떤 관계가 있는가?
* 역과 부동산 간 거리에 따라 가격 차이가 나타나는가?
* 이용량과 가격이 높은 지역은 어떤 공통적인 지역 특성을 가지고 있는가?

이를 통해 단순한 지역별 비교를 넘어 **교통·부동산·상권 데이터를 통합한 역세권 유형 분석**을 수행한다.

---

## 1.4 프로젝트 목적

본 프로젝트를 통해 다음의 목적을 달성한다.

1. **지하철 이용량과 역세권 부동산 가격의 관계를 분석한다.**

2. **지하철 이용량과 상권 규모 및 업종 특성의 관계를 분석한다.**

3. **역과의 거리, 인구, 상권, 업무시설 등 지역 특성을 고려하여 역세권의 특징을 분석한다.**

4. **분석 결과를 기반으로 서울 역세권을 유형별로 분류하고 주요 특징을 도출한다.**

---

## 1.5 분석 목표

최종 Power BI 대시보드를 통해 다음 질문에 답하는 것을 목표로 한다.

1. **서울에서 지하철 이용량이 가장 많은 역은 어디인가?**

2. **지하철 이용량과 부동산 가격 사이에는 어떤 관계가 있는가?**

3. **지하철 이용량과 상권 규모 및 업종 다양성 사이에는 어떤 관계가 있는가?**

4. **역과의 거리가 가까울수록 부동산 가격이 높은가?**

5. **서울의 역세권은 교통·부동산·상권 특성에 따라 어떤 유형으로 분류할 수 있는가?**

# 3. 분석 및 Power BI 대시보드 설계

### Question 1

# 3.3 Power BI 데이터 모델

```text
SQL Database
      ↓
Power BI 데이터 가져오기
      ↓
Fact Table + Dimension Table
      ↓
관계 설정
      ↓
Star Schema
      ↓
DAX Measure
      ↓
Visual
```

### 데이터 모델 설명

* **Fact Table:** 교통 이용량, 부동산 거래, 상권 데이터를 저장
* **Dimension Table:** 역, 날짜, 지역, 업종 정보를 저장
* **주요 관계:** Station / Date를 중심으로 각 Fact Table 연결
* **관계의 방향:** Dimension → Fact
* **기본 관계:** 1

# 3.4 주요 DAX 측정값

| 측정값       | DAX 개념   | 용도        |
| --------- | -------- | --------- |
| 총 지하철 이용량 | SUM      | 전체 승하차량   |
| 평균 역 이용량  | AVERAGE  | 역별 평균 이용량 |
| 총 거래량     | COUNT    | 부동산 거래건수  |
| 평균 부동산 가격 | AVERAGE  | 역세권 평균 가격 |
| 평균 평당 가격  | AVERAGE  | 가격 비교     |
| 총 점포 수    | SUM      | 상권 규모     |
| 신규 점포 수   | SUM      | 상권 성장     |
| 폐업 점포 수   | SUM      | 상권 쇠퇴     |
| 상권 증감률    | 전년 대비 비교 | 상권 변화     |
| 이용량 증감률   | 전년 대비 비교 | 교통 변화     |

예시:

```DAX
총이용량 =
SUM(Fact_Transit[total_usage])
```

```DAX
평균부동산가격 =
AVERAGE(Fact_RealEstate[price])
```

```DAX
총점포수 =
SUM(Fact_Commercial[store_count])
```

# Page 4. Insight & Action — 역세권 유형 및 인사이트

### 목적

분석 결과를 바탕으로 서울 역세권의 유형과 주요 특징을 도출한다.

### 예상 분석 유형

| 유형        | 교통 이용량 | 부동산 가격 |    상권 | 특징             |
| --------- | -----: | -----: | ----: | -------------- |
| 업무·상업 중심형 |     높음 |     높음 | 매우 높음 | 업무 및 상업시설 중심   |
| 주거 중심형    |     높음 |     높음 |    높음 | 주거 및 생활상권 중심   |
| 청년·문화 중심형 |     높음 |     중간 | 매우 높음 | 카페·음식점·문화시설 중심 |
| 주거·저밀도형   |     낮음 |     낮음 |    낮음 | 주거 중심 지역       |

※ 실제 유형과 특징은 군집분석 결과에 따라 결정한다.

### 핵심 Insight

**Insight 1**

지하철 이용량과 부동산 가격의 관계를 분석하여 교통 접근성이 부동산 시장과 어떠한 관련성을 갖는지 확인한다.

**Insight 2**

지하철 이용량과 상권 규모를 비교하여 교통량이 많은 지역에서 상권이 어떻게 형성되어 있는지 확인한다.

**Insight 3**

교통·부동산·상권 데이터를 종합하여 역세권 유형별 특징을 도출한다.

### Action Plan

| 발견된 문제                    | 분석 결과                   | 제안                  |
| ------------------------- | ----------------------- | ------------------- |
| 이용량이 높지만 상권이 상대적으로 부족한 지역 | 교통 유동인구 대비 상권 규모가 낮음    | 생활밀착형 상권 개발 가능성 검토  |
| 이용량과 부동산 가격이 모두 높은 지역     | 교통과 부동산 가치가 함께 높은 특성 확인 | 역세권 개발 및 주거 수요 분석   |
| 이용량은 높지만 주거가격이 낮은 지역      | 상업·업무 목적 이용 비중 가능성      | 주거 및 상업 기능을 구분하여 분석 |

※ 실제 Action은 분석 결과를 바탕으로 최종 결정한다.

# 9. 프로젝트 최종 점검

### 데이터

* [ ] 교통 데이터 출처가 명확하다.
* [ ] 부동산 데이터 출처가 명확하다.
* [ ] 상권 데이터 출처가 명확하다.
* [ ] Python으로 데이터를 수집했다.
* [ ] 전처리 과정을 기록했다.
* [ ] 역세권 기준을 명확하게 정의했다.
* [ ] SQL DB에 데이터를 저장했다.
* [ ] ERD가 작성되어 있다.

### SQL

* [ ] PK/FK가 적절하게 설정되어 있다.
* [ ] 교통·부동산·상권 테이블의 관계가 명확하다.
* [ ] JOIN을 활용했다.
* [ ] GROUP BY 및 집계 분석을 수행했다.
* [ ] 역별/기간별 분석 쿼리를 작성했다.

### Power BI

* [ ] 데이터 모델이 적절하다.
* [ ] 관계가 정상적으로 설정되어 있다.
* [ ] 주요 KPI Measure를 작성했다.
* [ ] 필터/슬라이서를 활용했다.
* [ ] 지도 시각화를 활용했다.
* [ ] 산점도를 활용하여 관계를 분석했다.
* [ ] 3개 이상의 분석 페이지를 구성했다.

### 분석

* [ ] 지하철 이용량과 부동산 가격의 관계를 분석했다.
* [ ] 지하철 이용량과 상권 규모의 관계를 분석했다.
* [ ] 역과의 거리와 부동산 가격의 관계를 분석했다.
* [ ] 역세권별 특성을 비교했다.
* [ ] 가능하다면 군집분석을 수행했다.
* [ ] 핵심 질문에 대한 답을 제시했다.
* [ ] 단순 차트 제시를 넘어 Insight를 도출했다.
* [ ] Insight를 바탕으로 Action을 제안했다.
